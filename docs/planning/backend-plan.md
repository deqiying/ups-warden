## 1. 计划原则

1. **先打通安全的采集链路，再做联动**。驱动只读防护、归一化和状态判定是一切联动的前提，必须在规则与关机之前完成并有测试覆盖。
2. **每个里程碑都能运行、能验证**。每个里程碑结束时 `gofmt -l .` 无输出、`go vet ./...` 与 `go test ./...` 通过，并有可演示的结果（模拟器驱动）。
3. **模拟器先行**。自动化测试不依赖真实设备（项目 `AGENTS.md` 的设备安全要求），模拟器与驱动同期开发。
4. **尽早给前端稳定的 API**。M4 结束时监控类 API 与 SSE 冻结，前端可并行开发总览、设备详情、设备管理页面。
5. **危险能力默认关闭**。新建的关机规则默认 dry-run；关机计划在 M7 完成全部幂等与恢复测试前不在演示环境启用真实动作。
6. **避免过度防御性编程，以明确契约代替层层兜底**。只处理当前支持范围、真实故障和明确安全要求；不为没有依据的极低概率场景增加兼容分支、自动修复或通用框架。具体边界见下节，不能以“精简”为由削弱设备安全、认证或数据一致性。

### 1.1 简洁性与防御边界

以下原则适用于后续实现和既有代码的精简评审。本轮已按审查结论精简 M0～M4 的具体问题，范围见 M4 后的精简记录；不代表可以删除所有防护分支。

- **校验放在信任边界，内部依赖已建立的契约**。HTTP 输入、Profile 导入、设备报文及持久化数据加载时验证必要约束；构造成功后，内部调用不逐层重复全量校验同一份未变配置。移除重复校验前先明确对象所有权和可变性，不能仅因上游曾校验就假定共享可变对象永远有效。
- **必需依赖缺失应尽早失败**。在装配或构造时确认必需模块；不在业务路径以 `nil` 判断返回空列表、跳过副作用或伪装成功。确有可选模块时明确其契约；测试使用显式替身，不为省略测试依赖给生产代码增加降级模式。
- **兼容必须有具体依据和范围**。协议规范、已确认设备样本、可复现问题或已承诺版本可作为依据；仅有“某设备可能这样返回”的猜测不够。待验证形式应标记为假设和验收缺口，不据此增加字段别名、类型转换或探测回退；未知输入明确失败或按既定质量语义标为无效。
- **输入范围由业务定义，不追求所有机器可表示值均可运行**。在入口统一限制周期、重试、大小和数量，超限明确拒绝；不为纳秒级轮询、整数极限或不支持的格式维护专用算法。边界测试应验证受支持范围和拒绝行为，而不是反过来扩大支持范围。
- **失败不能被兜底掩盖**。不把编码、存储、初始化或内部契约错误转换为空对象、默认值或成功结果。对外返回稳定错误码，对内保留不含凭据的操作、错误类别和必要定位信息；脱敏不能等同于丢掉所有诊断上下文。重试与恢复只用于已定义的可恢复失败，并有取消、退避或资源上限。
- **实现最小充分方案**。不预建未使用的扩展点、兼容层或未来类型分支；同一职责尽量有一个明确入口。为了兜底而引入全量重建、重复扫描等处理时，也须评估其正常运行成本，优先采用满足已知契约的有界处理。
- **必要防护不按概率删除**。设备只读发送 guard、外部报文长度/类型校验、认证/授权/CSRF、凭据保护、并发与事务一致性、取消/超时、有界队列及受管任务隔离均有明确故障后果。尤其 Profile 语义校验与发送前字节 guard 位于不同安全边界，不属于应合并删除的重复校验。

## 6. 质量门禁

每个任务合并前：

- `gofmt -l .` 无输出、`go vet ./...`、`go test ./...` 通过（项目 `AGENTS.md` 要求）。
- 新增公开 API 有文档注释；非显而易见的边界条件与失败语义有注释（简体中文）。
- 涉及时间逻辑的测试使用 `testing/synctest`，不使用真实 `time.Sleep` 等待。
- 涉及凭据的代码路径有"不回显、不入日志"的测试。
- 驱动相关改动必须让只读安全测试与架构测试通过。
- 新增防御或兼容分支须能说明：针对什么已知输入/故障、依据是什么、由哪一层负责，以及不用该分支会破坏什么契约；无依据的假设不作为实现要求。
- 简洁性评审检查重复全量校验、必需依赖的静默降级、吞错默认值、超出业务范围的极值支持及未使用扩展点；删除前核对调用链与既有安全/失败语义测试。
- 兼容测试须区分规范/样本证据与模拟假设；通过模拟器或 fuzz 不代表真实设备存在该兼容需求，也不替代 CP-1。

CI（Linux）额外执行 `go test -race ./...` 与短时 fuzz（每个 fuzz 目标 30 s）。CI 平台的具体搭建不在本计划范围内，如需要可在 M0 中追加任务。
