## 3. 端口与协议矩阵（2026-10-11 历史记录，禁止重新扫描）

```
TCP    80 : OPEN       ← HTTP WebUI + JSON 数据接口
TCP    53 : OPEN       ← DNS 解析器（意外）
TCP   502 : OPEN       ← Modbus TCP
TCP  2390 : OPEN       ← ayi9-json（AYI9 云监控卡 JSON API）
TCP 3493  : closed     ← 当时未发现原生 NUT 服务
TCP  443  : closed
TCP  161  : closed     ← SNMP 不走 TCP
TCP  162  : closed
UDP  161  : OPEN       ← SNMP v1/v2c（有响应）
UDP 5353  : no-response
UDP 162/123/1900/47808 : no-response
```

> 注：**关于扫描方法**——首轮全端口扫描（1–10000，并发 400）**仅命中 53**，漏掉了 80 / 502 / 2390；80 最先由单次 `curl` 确认，80 / 502 / 2390 随后由**低并发定向扫描**确认。判定：该设备对高并发连接**有限流**，全端口并发扫描结果**不可信**，上表以「定向复测」为准。另：2390 由设备自身配置页（`config_modbus.htm`）明确标注「TCP:2390, JSON format」。

## 4. 各协议详情

### 4.1 HTTP + JSON（TCP 80）— 历史观察，本项目禁止访问

原报告曾推荐此路径；该建议已被项目不访问设备 HTTP / WebUI 的安全约束取代。以下只保留已有响应与事故关联，不作为采集步骤。

#### 无鉴权可访问的内容

| 路径 | 说明 |
|---|---|
| `GET /` | 302 → `/en/` |
| `GET /en/` | 302 → `about.htm` |
| `GET /en/about.htm` | 设备信息页（型号、固件版本、psno） |
| `GET /en/monitor.htm` | 实时监控页（canvas 绘图） |
| `GET /en/monitor_data.htm` | **★ 实时数据 JSON 接口（核心）** |
| `GET /js/ups.js` | **前端主逻辑 JS，38685 字节，可无鉴权读取** |
| `GET /en/record.htm`、`alarm.htm`、`config*.htm`、`password.htm` | 各功能页 |

#### 关键数据接口

```http
GET http://<ip>/en/monitor_data.htm
```
- **无需任何凭据**（无 Cookie、无 `WWW-Authenticate`、无 `Set-Cookie`）
- 响应约 200 字节，`Content-Type: text/html`（实为 JSON）
- 响应头 `Cache-Control: no-cache`
- 支持 `/zh/` 与 `/en/` 两套 locale 前缀，**返回数据内容相同**

**响应结构**：
```json
{
  "ready": true,
  "func": 9,
  "model": "ET1K",
  "RTD": "(--- s9 ET1K 220 220 0.0 50 0.0 1/1 1K",
  "QAD": "(226.6 0.0 0.0 49.9 0.0 0.0 0.0 0 220.0 0.0 0.0 49.9 0.0 1.0 0.0 27 0 0 29.4 0 100 53.0 0000000000010011"
}
```

| 字段 | 类型 | 含义 |
|---|---|---|
| `ready` | bool | 设备数据就绪 |
| `func` | int | **功能位掩码**（`func=9` = 0x09） |
| `model` | string | 型号 |
| `RTD` | string | 额定信息，`(` 开头，空格分隔 **10 字段** |
| `QAD` | string | 实时数据，`(` 开头，空格分隔 **23 字段** |

**`func` 位掩码**（从 `ups.js` 反推）：
- `func & 0x08` → 支持保养放电（deep discharge）
- `func & 0x80` → 界面布局分支（疑与相数/机型有关；**未确认**）

#### 轮询节奏（来自 `ups.js`）

```javascript
setInterval(get_data, 3000);   // 每 3 秒轮询一次 monitor_data.htm
```
超时判定：超过 6000 ms 未响应则显示"通讯中断"。

#### 页面内的**写操作**入口（危险，勿盲试）

| 入口 | 说明 |
|---|---|
| `GET /en/monitor_action.htm?fun=N` | 开关机 / 自检 / 蜂鸣器控制（`fun` 为命令号） |
| `POST /en/login_form.htm` | 登录（字段 `inpass`） |
| `POST /en/config_modbus_form.htm` | 保存动环/SNMP 配置 |
| `GET /en/reset.htm` | **⚠️ 触发恢复出厂设置**（见第 7 节事故） |
| `GET /en/reboot_end.htm` | 重启提示页 |

#### 鉴权现状（**重要**）

- 已记录的响应头未见 `Set-Cookie` 或 `WWW-Authenticate`；这不能单独证明设备不存在其他会话或鉴权机制
- 未登录状态下：`about.htm`、`monitor.htm`、`monitor_data.htm`、`config*.htm`、`js/ups.js` **全部可读**
- **推断，未验证**：WebUI 的访问密码可能约束部分 `*_form.htm` 写入类端点；不能由公开页面可读推导出所有写端点的鉴权范围（见第 9 节）。

### 4.2 SNMP v1/v2c（UDP 161）

#### 该 agent 的特殊行为（**极易踩坑**）

| 行为 | 实测结果 |
|---|---|
| **GET** | ❌ 对**任何** OID 都返回 `noSuchName`（errstat=2） |
| **GETNEXT** | ⚠️ 仅对 `33.1.1.1.0` 有反应，之后即终止 |
| **GETBULK** | ✅ **唯一可用的读取方式**，可一次取回整表 |
| **request-id 编码** | ⚠️ **仅接受 4 字节编码**（`02 04 xx xx xx xx`）；1 字节编码被**静默丢弃**（表现为超时） |
| community | 仅一个配置值有效，其余测试值及空值无响应（实际值已脱敏）；不把历史测试值当作连接凭据或继续枚举 |
| 协议版本 | v1 与 v2c **均可用**（v2c 是 GETBULK 的前提） |
| **SNMPv3** | **未观察到响应**（21 次探测 0 响应，8 个候选端口均无响应，配置页无 v3 参数）；不足以证明所有配置下均不支持 |
| 稳定性 | ✅ GETBULK 连续 8 次，均返回 58 varbind / 40 个有值 OID，字段集完全一致 |

> **对项目的影响**：标准 `snmpwalk`、Zabbix / LibreNMS 通用模板**大概率无法直接使用**。要实现 SNMP 采集，必须自行构造 GETBULK 报文（或使用能指定 request-id 编码方式的库）。

#### MIB 子树

位于 **RFC 1628 UPS-MIB**（`1.3.6.1.2.1.33`）。**经核实，该设备对 RFC 1628 的实现基本忠实**（分组、标量/表结构、列序号均吻合），仅个别表格列偏移有小偏差。

### 4.3 Modbus TCP（TCP 502）

#### 功能码支持性（实测穷举）

| 功能码 | 名称 | 结果 |
|---|---|---|
| **FC03** | Read Holding Registers | ✅ **唯一支持** |
| FC01 | Read Coils | ❌ IllegalFunction (0x01) |
| FC02 | Read Discrete Inputs | ❌ IllegalFunction |
| FC04 | Read Input Registers | ❌ IllegalFunction |
| FC07 | Read Exception Status | ❌ IllegalFunction |
| FC08 | Diagnostics | ❌ IllegalFunction |
| FC11/12 | Comm Event Counter/Log | ❌ IllegalFunction |
| FC17 | Report Server ID | ❌ IllegalFunction |
| FC20/23/24 | File/FIFO | ❌ IllegalFunction |
| FC43 | Read Device ID | ❌ IllegalFunction |
| FC05/06/15/16/21/22 | 写入类 | ⚠️ **主动跳过未测试**（安全考量） |

#### 地址空间

```
可读范围：0 .. 79  （共 80 个寄存器）
reg 0..79   → OK
reg 80+     → IllegalDataAddress (0x02)
```

#### Unit ID 行为

`unit id = 0 / 1 / 169 / 255` **返回完全相同的数据** → 该 TCP 从站**不校验 Unit ID**。
（配置页显示 `my addr = 169`，推测 TCP 502 是其内部 RS485 从站表的桥接。）

#### 寄存器映射（实测交叉验证）

**已确认**（与 QAD / SNMP 同一时刻数值精确对应）：

| 寄存器 | 缩放 | 对应量 | 同时刻三方值 |
|---|---|---|---|
| `reg00` | ×10 | 输出电流（S 相） | QAD[13]=1.0 → reg00=10 |
| `reg02` | ×10 | 输出电压 R | QAD[8]=220.0 → reg02=2200 |
| `reg08` | ×10 | **电池电压** | QAD[18]=29.4 → reg08=294；SNMP=294 |
| `reg10` | ×10 | **电池容量 %** | QAD[20]=100 → reg10=1000；SNMP=100 |
| `reg13` | ×10 | 机内温度 | QAD[21]=53.0 → reg13=530；SNMP=53 |
| `reg16` | ×10 | 输入频率 | QAD[3]=49.9 → reg16=499；SNMP=499 |
| `reg17` | ×10 | **输入电压 R** | QAD[0]=226.6 → reg17=2266；SNMP=226 |
| `reg23` | ×1 | 输入有功功率 | SNMP=2970 |
| `reg27` | ×10 | 输出频率 | 499；SNMP=499 |
| `reg28` | ×10 | 输出电压 | 2200；SNMP=220 |
| `reg34` | ×1 | 输出功率 (VA) | SNMP=2700 |
| `reg45` | ×10 | **负载百分比 R** | QAD[15]=27 → reg45=270；SNMP=27 |
| `reg49` | ×10 | 旁路频率 | 499 |
| `reg50` | ×10 | 旁路电压 | 2266 |
| `reg56` | ×1 | 旁路功率 | 2700 |

**疑似分组结构**（输入 / 输出 / 旁路三组，各组以「频率 → 电压 → 电流 → 功率」排列，与 SNMP 组**一一对应**）：

```
输入组   reg16=频率  reg17=电压  reg18=电流  reg23=功率
输出组   reg27=频率  reg28=电压  reg29=电流  reg34=功率  reg45=负载%
旁路组   reg49=频率  reg50=电压  reg51=电流  reg56=功率
电池     reg08=电压  reg10=容量  reg13=温度
```

**未确认的寄存器**（实测非零但语义不明）：
`reg01=17`、`reg05=500`（疑为输出频率设定值/额定值）、`reg64=19`（数值会变，疑为计数器或累计量）

> ⚠️ 厂商另有《CLOUD云-MODBUS协议.pdf》寄存器对照表，**本次未能取得**（官网下载链接需交互、PDF 为 CID 字体无法提取）。建议项目文档注明"寄存器表以厂商文档为准"，并保留实测校准能力。

#### 重要限制

- **Modbus 侧没有任何时间字段**：已放电时间 / 剩余时间**均不存在**（已用 SNMP 秒计数做同步差分验证：120 秒内无任何寄存器增减 ±120）
- 报文中**无设备标识**（无 FC17 Report Server ID）→ 无法通过 Modbus 确认对端身份

### 4.4 AYI9 云监控卡 JSON API（`ayi9-json`，TCP 2390）— **能力最全**

#### 厂商文档（已获取）

厂商**深圳市依玖技术有限公司**公开文档：《云监控卡 API 接口说明（Http 和 TCP/IP 通讯）》
→ 该文档描述了本协议的完整规范（指令表、错误码、字段定义、状态字位定义）。

#### 传输特征

| 项目 | 实测值 |
|---|---|
| 报文方向 | 无被动推送，**请求-应答**模式 |
| 请求格式 | 单行标准 JSON（末尾换行可选） |
| 响应格式 | 单行标准 JSON |
| **延迟** | **≈ 29 ms**（单次往返，实测 35 req/s） |
| 流水线 | ❌ 不支持（一次连接发多条命令，只回第一条） |
| 常连 | 文档要求「TCP/IP 要保持常连模式」 |

#### 请求字段

| 字段 | 必需 | 说明 |
|---|---|---|
| `cmd` | ✅ | **指令（必须大写）** |
| `session` | 文档称必需 | 指令序号，用于标识返回归属；**实测可省略** |
| `pass` | 可选 | 管理卡密码。密码为空时可省略 |
| `new_pass` | — | **写入**：设置新密码（`clear` 表示清空） |
| `host` | — | **写入**：返回结果的目标 URL（HTTP 模式用） |

#### 已知指令

| 指令 | 类型 | 实测返回 | 说明 |
|---|---|---|---|
| `QAD` | **读** | ✅ 实时数据（23 字段） | 查询 UPS 实时数据 |
| `RTD` | **读** | ✅ 额定信息（10 字段） | 查询设备额定信息 |
| `T` | 读? | ⚠️ `FAILED` | 文档列为"查询"，本机返回失败 |
| `SON` | 🔴 **写** | `FAILED`（本机拒绝） | **控制 UPS 开机** |
| `SOFF` | 🔴 **写** | ⚠️ **`OK`（执行成功！）** | **控制 UPS 关机** |
| `BZON` / `BZOFF` | 🔴 **写** | `FAILED` | 控制蜂鸣器 |
| `new_pass` | 🔴 **写** | 未测试 | 改密码 |
| `host` | 🔴 **写** | 未测试 | 改上报目标 |

> 文档原文："包括但不限于以下指令：RTD，QAD，SON，SOFF，BZON，BZOFF，T"
> 指令列表并不穷尽；**禁止枚举未公开指令**，仅使用项目读指令白名单。

#### 响应格式

**成功**：
```json
{"uid":"<DEVICE_SERIAL>@ayi9.com","session":"1234","cmd":"QAD","value":"(0.0 0.0 ... 0000000010010100"}
```
**失败 / 参数错误**：
```json
{"uid":"<DEVICE_SERIAL>@ayi9.com","cmd":"get","value":"FAILED"}
```

#### 错误码（厂商文档）

| 码 | 含义 |
|---|---|
| 101 | JSON_FORMAT — JSON 格式错误 |
| 102 | SESSION_LOSS — 缺 session 字段 |
| **103** | **PASSWORD_ERROR — 密码错误** |
| 104 | HOST_NO — 缺 host 字段 |
| 105 | COMMAND_NO — 缺指令字段 |
| 106 | PASSTOOLENGTH — 密码超 15 位 |
| 201 | BUSY — 系统繁忙 |
| 410 | bad request（实测，参数不合法时返回） |

#### 鉴权观察（仅限探测当日）

- 协议**内建 `pass` 机制**（错误码 103 已定义）
- 当时未配置密码；这不是当前凭据状态的声明
- ⚠️ **历史观察**：传入错误的 `pass` 仍能读取 QAD；只说明该样机当时的读请求未拒绝此值，不能证明所有机型或控制指令都不校验密码
- **未验证**：此 `pass` 与 WebUI 访问密码是否同一套

### 6.3 工作状态字（QAD[22]，16 字符 = b15…b0）★

来源：厂商文档；**已由 SOFF 事件实测验证 b5**。

| 位 | 含义 |
|---|---|
| b15 | UPS 类型：0=ONLINE，1=BACKUP |
| b14–b12 | 保留 |
| b10–b11 | 电池自检放电结果：00=未知，1=失败，2=成功 |
| b9 | 保留 |
| **b8** | **0=不过载，1=过载** |
| **b7** | **0=市电正常，1=市电不正常** ✅ 已实测（停电期间=1） |
| **b6** | **0=电池电压不低，1=电池电压低** |
| **b5** | **0=运行，1=正在关机或已关机** ✅ 已实测（SOFF 后翻转） |
| b4 | 0=蜂鸣器开启，1=蜂鸣器静音 |
| b0–b3 | UPS 状态：0=POWER_ON 1=STANDBY 2=BYPASS 3=LINE 4=BAT 5=TEST 6=FAULT 7=CONVERTER 8=HE 9=SHUTDOWN |

**探测时样本值** `0000000000010011` → b7=0（市电正常），b5=0（运行），b0-b3=`0011`=3 → **LINE（市电工作状态）**

**停电期间实测值** `0000000010010100` → b7=1（市电异常），状态=4 → **BAT（电池供电）**

> ⚠️ **迁移注意**：厂商文档中 b10–b11 的写法与 b15…b0 顺序存在歧义。按需求附录 B.3 的证据分类，状态码 3 / 4、b5、b7 有历史观察，b6 低电位来自文档定义，不能一并称为已实测；跨机型仍需独立验证。

## 7. ⚠️ 安全与风险警示（**必读**）

本次探测过程中**触发了两起真实事故**，均因访问了设备的写操作端点/指令。这些是设计项目时必须内建防护的依据。

### 事故 1：`reset.htm` 触发出厂重置

- **经过**：在批量探测页面清单时，以 `GET /en/reset.htm` 访问
- **后果**：设备进入恢复出厂设置流程；随后约 1 分钟内 HTTP 不可达、ping 丢包 50%
- **恢复**：自行恢复，`psno` 未变（具体序列号已脱敏）
- **教训**：**该 WebUI 的写操作可由 GET 触发**，无二次确认、无 CSRF 令牌

### 事故 2：`{"cmd":"SOFF"}` 疑似触发关机指令

- **经过**：在测试厂商文档所列指令时，向 `ayi9-json`（TCP 2390）发送 `{"cmd":"SOFF"}`
- **返回**：`"value":"OK"` —— 按文档为"执行成功"
- **实测证据**：状态字由 `0000000010010100` 变为 `0000000010110100`，**差异仅在 b5**（文档定义：1 = 正在关机或已关机）
- **后果**：**UPS 输出未被切断**（连续监测 45 秒，输出稳定 220.0 V，负载正常）；市电恢复后状态字归零、状态回到 `LINE`
- **未确认**：SOFF 是否会在特定条件下（如电池耗尽）真正切断输出 —— **此风险未排除**

### 风险要求与现行约束的对应

以下保留原 R1~R6 编号，便于需求追溯；安全边界按现行项目规范收紧，并注明未采用的旧建议。

| 编号 | 要求 |
|---|---|
| **R1** | **驱动接口必须不暴露写操作**。Modbus 仅放行 FC03/FC04；SNMP 禁用 SET；`ayi9-json` 仅白名单读指令（`QAD`/`RTD`）。 |
| **R2** | 原建议为写操作默认关闭、dry-run 和审计；本项目**不实现 UPS 本体控制**，不能通过配置开启设备写请求。受控主机动作的 dry-run / 审计属于另一个边界，见需求 SEC-02、FR-ACT-04。 |
| **R3** | 受控主机的危险动作需二次确认、幂等与持久化保护；这些规划不构成执行 UPS 写指令的许可。 |
| **R4** | 原建议仅禁止探测未声明的 URL；现行规则更严格：**禁止访问任何设备 HTTP / WebUI 路径**。 |
| **R5** | 关机编排需去抖、每步超时、失败审计与先关负载；原建议中的「再通知 UPS」**不采用**。规划的最后阶段是关闭 ups-warden 所在主机，不是发送 UPS 控制指令。 |
| **R6** | 明确"`ayi9-json` 存在未公开指令"这一事实 —— **禁止对 `cmd` 字段做字典爆破**。 |

### 另外的暴露面（非 UPS 功能，但存在于同一设备）

- **无鉴权的数据读取**：局域网内任何人可读全部 UPS 实时状态（HTTP / 502 / 2390）
- **SNMP 使用默认 community 的风险**（历史观察；实际凭据不公开）
- **开放递归 DNS 解析器**（53）

## 8. 原始设计建议及采用边界

本节保留探测当时的建议，不是当前方案。产品范围见[需求草案](../../planning/requirements.md)，技术取舍与替代理由见[后端方案](../../../.agents/notes/proposed/architecture/2026-10-11-backend-design.md)第 2.1、21.1 节。

### 8.1 历史协议优先级（不采用）

原排序如下，保留用于解释设计演变。当前 P0 规划三种只读驱动：SNMP、Modbus TCP、`ayi9-json`；HTTP JSON 已排除，不能按下表实施。

| 优先级 | 协议 | 理由 |
|---|---|---|
| **P0** | **HTTP JSON** (`monitor_data.htm`) | 无鉴权、单请求 200 字节拿全量、字段最全、延迟低 |
| **P1** | **SNMP v1/v2c + GETBULK** | 行业标准、跨厂商通用性最好、**唯一提供"已放电时间"** |
| **P2** | **Modbus TCP (FC03)** | 工业场景常见，但本机能力最弱；需设备 profile 映射寄存器 |
| **P3** | AYI9 云监控卡 JSON API（`ayi9-json`） | 能力强（含控制），但**厂商私有、跨品牌不通用** |
| ❌ | NUT | 当时未发现原生 NUT 服务；不能据此否定经其他驱动接入的可能性 |

### 8.2 通用化设计要点

1. **设备 Profile 驱动映射**，不要硬编码 OID / 寄存器地址
   本机即为反例：SNMP 厂商名是占位符 `'---'`、旁路表列偏移与 RFC 1628 不同、Modbus 寄存器表无公开文档。
   Profile 应包含：`{字段名, 地址/OID, 类型, scale, offset, 枚举映射, 单位}`。

2. **两级"剩余时间"策略**（必须）
   - 优先读原生字段（QAD[19] / `33.1.2.3.0`）
   - 读到 `0`/无效时**自动降级**为自算：
     `剩余时间 ≈ 当前容量% ÷ 放电速率(%/min)`（速率用滑动窗口自校准）
   - ⚠️ **本机实测放电速率 ≈ 1.0–1.1 %/min**（负载 25%，1 kVA）→ 满量程约 90 分钟
   - 关机触发**不要用估算值**，应用「容量阈值 + 放电持续时长」双条件

3. **SNMP GETBULK 与 request-id 编码的历史建议**
   原报告认为 GET / GETNEXT 限制会影响通用工具读取，并列出自研或 `gosnmp` 的候选方向；没有保存相应库版本的兼容性验证记录。
   后端方案 D1 已选择自研最小只读子集，理由见其第 2.1 节；不把旧候选描述当作已验证的库能力。

4. **不要假设"市电/电池"只有一个来源**
   本机有 3 个独立来源（QAD[0] 电压 / 状态字 b7 / SNMP 输入组），建议**取多源交叉验证**再判定，避免单点误判触发关机。

5. **"已放电时间"只能来自 SNMP**
   若项目只实现 Modbus 或 HTTP，则必须自行记录进入电池模式的时间戳。

### 8.3 历史驱动与控制接口草案（不采用）

以下保留原提案，**不是当前接口契约，也不得实现其中的 `Controllable`**。归一化应在驱动之外完成，现行只读接口方案见需求第 4.1 节和后端方案第 5.1 节。

```go
// 探测设备身份与能力
type Driver interface {
    Probe(ctx context.Context) (DeviceInfo, error)
    Poll(ctx context.Context) (Snapshot, error)
    Caps() Capabilities   // 声明本驱动是否支持控制、支持哪些字段
}

// 控制能力必须与只读采集分离，且独立开关
type Controllable interface {
    // 默认不注册；仅在用户显式启用且通过安全前置检查后可用
    Shutdown(ctx context.Context) error
    SetMode(ctx context.Context, m Mode) error
}
```

### 8.4 不建议做的事

- ❌ 对 `ayi9-json` 的 `cmd` 做字典爆破（存在未公开指令，可能触发控制）
- ❌ 用 SNMP SET 实现控制（本设备无 `33.1.8` 控制组，且 agent 残缺）
- ❌ 依赖 Modbus 获取时间信息
